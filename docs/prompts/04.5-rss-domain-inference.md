# Prompt 4.5 — RSS domain inference

**Status:** built and smoke-tested. Lead-with-domain count went from ~2 → ~11 per smoke run.

## What it fixed

After the Prompt 4 workers app went live, the `events` table showed that **every RSS-sourced lead was being skipped at ingest** because `domain: null`. Root cause: RSS feed descriptions don't reliably embed `<a href="company-website.com">` links — they cite the funding amount, stage, and a one-line product description, but rarely the company's URL. The `extractCompanyUrl()` heuristic in `rss/extractors.ts` returned `null` for most items, and `apps/workers/src/lib/ingest.ts` correctly drops leads without a domain (no way to dedupe or contact-find without one).

## What it added

A two-layer domain resolution strategy in `packages/scrapers/src/rss/index.ts`:

1. **Layer 1 (existing):** `extractCompanyUrl()` — look for an `<a href="...">` in the article body
2. **Layer 2 (new):** `inferDomainFromName(name, geoHint)` — if Layer 1 returns null, probe common TLDs for `<slug>.<tld>` via HEAD requests

## How `inferDomainFromName` works

```
"Anscer Robotics" + geoHint: "india"
    │
    ▼  nameToSlug()
"anscerrobotics"                                     ← strip "labs|inc|llc|...", non-alnum
    │
    ▼  TLD_CANDIDATES["india"]
[".in", ".co", ".com", ".io", ".ai", ".tech"]        ← geo-ordered
    │
    ▼  probeFirst()
[anscerrobotics.in, anscerrobotics.co, ...]          ← batch 3 at a time
    │
    ▼  HEAD https://<candidate> (3s timeout)
First response with status < 400 wins
    │
    ▼
"anscerrobotics.com"                                 ← hit
```

### Geo hint → TLD priority

| Geo hint | TLD order |
|---|---|
| `india` | `.in, .co, .com, .io, .ai, .tech` |
| `sea` | `.sg, .com, .co, .io, .ai, .id, .vn` |
| `global` | `.com, .io, .ai, .co, .dev, .app` |

`geoHintFromSourceDomain()` derives the hint from the feed URL — Inc42/YourStory/IndianStartupNews/StartupTalky → india; e27/Vulcan Post → sea; TechCrunch → global.

### Safety rails

- **Slug length bounds:** rejected if `< 2` or `> 30` chars after slugging. Catches mangled names like "KPay, a financial management platform for SMEs" (slug "kpayafinancialmanagementplatformforsmes" → 39 chars → bailed without any probes).
- **3-second HEAD timeout per probe** via `AbortController` — one slow DNS doesn't hang the whole scrape.
- **Concurrency limit 3** — `Promise.all(batch.map(probeDomain))` in batches of 3. Don't slam DNS or any single domain.
- **HEAD method** instead of GET — minimal bandwidth, no body parsing.
- **No retries on probe failure** — if a domain returns 405 (Method Not Allowed for HEAD), we treat it as "miss" and move on. False negatives accepted.

## Where the misses come from

Domain misses fall into two categories:

1. **Name extraction kept descriptors.** `extractCompanyNameFromTitle()` captured "Travel-fintech startup Scapia" instead of just "Scapia". The slug `travelfintechstartupscapia` doesn't match `scapia.com`. Fixing this requires improving the name regex in `rss/extractors.ts` — out of scope for this prompt.
2. **Real domain doesn't follow the slug pattern.** Some companies use abbreviations, parent-brand domains, or rebrands that name → slug → TLD probe can't catch.

Both are **expected**. The spec called this out: "False negatives are acceptable — that lead just gets skipped at ingest." Improving (1) is a future tuning opportunity once we have data on which lead-misses cost us actual outreach opportunities.

## Deviations from spec

None of substance. Followed the spec implementation verbatim. The barrel re-export in `src/utils/index.ts` (`export * from "./domain.js"`) automatically picked up the new `inferDomainFromName` and `nameToSlug` exports, so no change needed in `src/index.ts`.

## What to remember from this prompt

- **Two-layer domain resolution** is the pattern: parse → infer. Future enrichment (Prompt 5) can add a third layer (LLM lookup via name+description) if needed.
- **Slug safety rails matter.** Without the length check, we'd burn 6 HEAD requests on every long-name lead. The 30-char cap is conservative; can be raised once we see false negatives we'd want to recover.
- **HEAD probes are cheap but cumulative.** 56s for ~14 leads across 7 feeds is fine for cron, would be terrible for a synchronous user request. Don't put `inferDomainFromName` on a hot path.
- **The fix is upstream of ingest.** `apps/workers/src/lib/ingest.ts` still skips null-domain leads — that's correct; we just give it fewer nulls to skip.
